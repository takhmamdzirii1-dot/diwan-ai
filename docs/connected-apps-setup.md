# Connected Apps setup

Google Drive's deployed read adapter is preserved. This package adds server-side Gmail, GitHub, Canva, Google Docs/Sheets, Shopify Admin and WooCommerce adapters, plus an encrypted, exact-action review queue. **These new adapters are fixture-tested, not live-verified. Production verification on October 2 found no connector OAuth variables in the project serving joinvantra.com. The nine-group package is not complete or ready for public launch.** Shopify onboarding stays disabled until mandatory privacy/uninstall webhooks are implemented. Meta Ads, Facebook/Instagram and WhatsApp onboarding/actions remain unimplemented; do not advertise them as connectable. The Example Files adapter remains an opt-in fixture, never a real connection.

## One setup checklist

### Production configuration diagnostics

The authenticated connector-list route logs `CONNECTED_APPS_CONFIGURATION` once per changed configuration/process. It records only allowlisted prerequisite presence/nonblank booleans, exact flag validity/enabled booleans, and disabled reasons; it never returns these diagnostics to the browser or logs credential values. An empty HTTP-200 list is distinct from the route's HTTP-503 database/service failure.

Production's empty-list incident was traced to `PROVIDER_TOKEN_ENCRYPTION_KEY` being absent at runtime, while every implemented OAuth credential pair was present and both enable flags were valid/enabled. Restore the existing key from authorized private configuration, never generate/rotate a replacement casually. Environment-variable names in deployment metadata do not prove nonempty runtime values. Verify the authenticated list after the Git deployment; configuration availability is not a live OAuth/read test. Shopify and Meta/WhatsApp remain deliberately disabled as described below.

1. In [Google Cloud](https://console.cloud.google.com/apis/library/drive.googleapis.com), enable Google Drive API. In [Google Auth Platform](https://console.cloud.google.com/auth/clients), create a **Web application** OAuth client. Configure branding/audience and add the authorized QA account as a test user while the app is in testing.
2. Register exact redirect URIs:
   - Production: `https://joinvantra.com/api/connected-apps/oauth/callback`
   - Local QA on port 3103: `http://localhost:3103/api/connected-apps/oauth/callback`
   - Use a separate local client if appropriate. Preview deployments are deliberately not OAuth callback origins.
3. For the existing Drive connection request only `openid`, `email`, and `https://www.googleapis.com/auth/drive.readonly`. It remains read-only. It is a restricted Google scope: complete the [required verification](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) before public launch. Docs/Sheets writes use a separate `drive.file` grant; they do not silently broaden existing Drive consent.
4. Enter values privately in the worktree's ignored `.env.local`, and in the project’s Vercel **Settings → Environment Variables** for the intended environment:
   - `GOOGLE_DRIVE_CLIENT_ID`
   - `GOOGLE_DRIVE_CLIENT_SECRET`
   - Local production-style QA only: `CONNECTED_APPS_ORIGIN=http://localhost:3103`. Production defaults to `https://joinvantra.com`; do not set a localhost origin in Vercel Production.
   - `PROVIDER_TOKEN_ENCRYPTION_KEY` — reuse the existing configured key; never rotate it casually. If absent, create a strong random secret in a password manager. Do not use `NEXT_PUBLIC_`, paste secrets in Chat, or commit local env/session files.
5. Restart local code. Open Studio → Settings → Connected apps → Google Drive → Connect. Complete consent yourself. Confirm the displayed Google email matches the account you selected. Then ask Chat to summarize one small QA Google Doc or text/CSV file using its exact `docs.google.com`/`drive.google.com` URL. Disconnect and confirm access is removed. If remote revocation fails, the UI explicitly says only VANTRA access was removed; remove the grant in [Google account permissions](https://myaccount.google.com/connections).

## Supported and bounded

- Google Docs/Sheets/Slides export to text/CSV; plain text, Markdown and CSV download directly. Binary PDFs, images and arbitrary external endpoints are not supported.
- One explicit file per turn. Credentials and connection metadata never enter the model context. At most 120 KB fetched, 30,000 text characters accepted, and 8,000 relevant characters passed to the model. Unclear large-file relevance fails closed.
- Native-tool routes execute `read_connected_file`, then synthesize or create an existing artifact with the same selected model. Routes without verified tool calling use the existing authorized server-read context path.
- Granted scopes and ownership are rechecked when the tool executes. Connecting alone never authorizes background reads or writes. Refresh is lazy; disconnect clears local access before attempting remote revocation. Concurrent refresh cannot resurrect a disconnected grant.
- The registry only enables Google Drive when its client ID, client secret and encryption key are configured. Missing setup must never appear as a successful connection.

Consult the linked provider dashboards for current account-specific pricing before enabling consequential actions.

## Review/execution guarantees and remaining work

- Chat can only prepare an encrypted exact-action review from a current explicit write request. Connecting is not permission. The authenticated owner confirms the stored action/target/content in Settings → Connected apps; client-provided replacement payloads are not accepted.
- Ownership/scopes and the connection's verified account/grant are rechecked at execution. A reconnect invalidates old reviews; token refresh does not. One atomic claim dispatches once. An uncertain outcome stays unknown and cannot automatically retry. This is not a promise of global provider-level exactly-once delivery across separately created user requests.
- Parameterized adapters require verified native tool calling; unsupported routes fail before a model invocation rather than guessing parameters. The original no-argument Drive server-read path remains intact. Only one relevant connector action is exposed per turn; multi-connector requests fail clearly rather than injecting every catalog.
- Existing artifact creation from a connected read remains supported. Reviewed external creation is a pending proposal, not a local artifact or a completed external action.
- Action review records contain encrypted private content. A production retention/cleanup policy and real SQL concurrency verification remain required before launch. A process killed after dispatch may leave `executing`; do not resubmit blindly—reconcile with the external service.
- Missing configuration is not a successful connection. No new OAuth grant, real connector execution, paid model request, advertising spend or production data mutation was performed in this package's fixture verification.
